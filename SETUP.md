# Setup

This replaces the GitSkins-hosted images with SVGs generated by your own script and
committed straight into your `mihonrado/mihonrado` repo — so there's no watermark and
nothing hotlinked to a third party.

## 1. Copy these files into your repo

Copy everything here (`scripts/`, `.github/workflows/`, `assets/`, `README.md`) into
the root of your `mihonrado/mihonrado` repository, replacing the existing `README.md`.

## 2. Commit and push

```bash
git add .
git commit -m "Self-host README assets, drop GitSkins watermark"
git push
```

## 3. Let the Action run

The workflow at `.github/workflows/update-readme-assets.yml` will:
- run once a day at 03:00 UTC,
- run any time you push changes to `scripts/`,
- and can be triggered manually from the **Actions** tab (`Run workflow`).

It uses the repo's built-in `GITHUB_TOKEN` (no extra secret needed) to pull your public
GitHub data — profile, repos, languages, contribution calendar, pinned repos — and
regenerates the SVGs in `assets/`, committing them back automatically.

The first time it runs, it'll replace the placeholder SVGs currently in `assets/` with
real data pulled from your account.

## 4. Run it locally (optional)

```bash
npm install --no-save   # no dependencies needed, just Node 18+
GITHUB_USERNAME=mihonrado GITHUB_TOKEN=<a personal access token> node scripts/generate-assets.mjs
```

A token isn't strictly required for the basic profile/repo/language data, but it **is**
required for the contribution heatmap and pinned-projects sections (those use GitHub's
GraphQL API). Any token works — it doesn't need special scopes for public data, just
`public_repo` read access or none at all for a fine-grained read-only token.

## Customizing

- Colors/fonts live in `scripts/lib/theme.mjs`.
- Each card is its own file under `scripts/lib/sections/` — edit freely.
- To add/remove sections, just add/remove `<img>` tags in `README.md` pointing at the
  corresponding `assets/*.svg`.
